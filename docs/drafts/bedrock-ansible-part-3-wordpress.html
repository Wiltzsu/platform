Personal platform · Part 3: provisioning a Bedrock site with Ansible

After hardening the server and centralizing Laravel deploys, the next piece of my platform work was the dev blog itself — a Roots Bedrock WordPress site that had only ever run locally at http://site.local.

An existing Laravel app already lives on the same box. I did not want a second manual nginx-and-MySQL ritual every time I add a site. Phase 1 of putting the blog online is host provisioning: nginx vhost, PHP-FPM, database, directory layout, and a first .env shell — automated with Ansible in the platform repo. Code deploy and DB migration come in Part 4.

Decisions up front

  • Same server as the Laravel app — one nginx host, multiple vhosts.
  • No staging for now — straight to production; staging convention comes later.
  • SSH / deploy user — user (same user and GitHub Actions secrets as the Laravel app).
  • Deploy path — /var/www/site (domain-based path, not repo name).
  • MySQL — one database per app, but I reuse the existing MySQL user user (same pattern as my other sites).
  • Database migration — export local WordPress DB, import on the server, then wp search-replace (Part 4).

Two layers (again)

Part 3 is phase 1. Same split as Laravel: platform owns the playbook; the app repo owns the deploy workflow.

Prerequisites

  • Server already hardened (bootstrap-server.yml or equivalent checklist).
  • Deploy user user with sudo, www-data group, and GitHub Actions deploy key in authorized_keys.
  • MySQL running on 127.0.0.1.
  • DNS A record for the site (and www) pointing at the server — needed before certbot, not necessarily before Ansible.
  • ansible-galaxy collection install -r requirements.yml (includes community.mysql).
  • Inventory file — copy inventory/hosts.example.yml to hosts.yml (gitignored). Use your SSH config alias or explicit key path — bare ssh user@ip fails if your key is not the default.

Inventory and SSH

On my laptop, ~/.ssh/config might look like:

Host server
  HostName YOUR_SERVER_IP
  User user
  IdentityFile ~/.ssh/id_ed25519

inventory/hosts.yml:

all:
  hosts:
    production:
      ansible_host: server
      ansible_user: user

If the key has a passphrase, load it once per terminal: eval "$(ssh-agent -s)" && ssh-add ~/.ssh/id_ed25519. Ansible uses become: true globally in ansible.cfg, so pass -K for your sudo password.

Site variables: site_bedrock.yml

cp ansible/group_vars/site_bedrock.example.yml ansible/group_vars/site_bedrock.yml

Example production values:

bedrock_site_name: site
bedrock_domain: site.example.com
bedrock_domain_aliases:
  - www.site.example.com

bedrock_deploy_path: /var/www/site
bedrock_deploy_user: user

bedrock_php_version: "8.4"

bedrock_db_name: site
bedrock_db_user: user
bedrock_db_password: "…"  # quote if it contains $
bedrock_db_host: "127.0.0.1"

bedrock_wp_home: "https://site.example.com"
bedrock_wp_env: production

Secrets stay in this gitignored file (Ansible Vault later). The playbook templates .env on the server only if it does not exist yet.

Run the playbook

cd platform/ansible
ansible-playbook -i inventory/hosts.yml playbooks/site-bedrock.yml -K

--check is useful for nginx and paths, but it can fail on php8.4-fpm because packages are not actually installed in dry-run mode. A real run installs python3-pymysql on the server (now in the role) so MySQL tasks work.

On success: database site, /var/www/site, nginx vhost with docroot …/web, and a fresh .env template. curl -H "Host: site.example.com" http://127.0.0.1 returned 403 until application code lands — expected.

Gotchas that bit me

  • Reusing MySQL user user — the first version of the role used mysql_user without append_privs: true. That replaced all grants with only site.*. The Laravel app hit HTTP 500 until I restored GRANT ALL ON app1.* (and the other app DBs). Fix in the role: append_privs: true.
  • Quote passwords with $ — in Laravel .env, unquoted DB_PASSWORD=foo$bar can truncate at $. Use single quotes: DB_PASSWORD='…'.
  • bedrock_db_password: CHANGE_ME — sets that literal in MySQL. Use a real password before you run.
  • Deploy path everywhere — site_bedrock.yml and the Bedrock repo’s deploy.yml must both use the same deploy_path.
  • nginx default site — the role removes it. Confirm other vhosts stay enabled.
  • PHP 8.4 — same as the Laravel app on this host; Bedrock only requires >=8.3.
  • .env salts — template ships generateme. Replace from roots.io/salts.html before go-live.

What the role does not do

  • SSL — certbot after the site responds on port 80.
  • Application code — GitHub Actions deploy (Part 4).
  • WordPress core — composer install after code lands.
  • DB import — export local, import, wp search-replace.

After Ansible

  1. Verify: SHOW DATABASES LIKE 'site'; and SHOW GRANTS FOR 'user'@'localhost';
  2. Fix /var/www/site/.env (salts, quoted DB_PASSWORD).
  3. Wire the Bedrock repo’s deploy.yml → reusable-deploy-bedrock.yml (Part 4).
  4. Import local DB + rsync web/app/uploads/.
  5. wp search-replace 'http://site.local' 'https://site.example.com' --all-tables
  6. sudo certbot --nginx -d site.example.com -d www.site.example.com
